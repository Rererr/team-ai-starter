# team-ai-starter

TeamAIで配布する、チームのルール・知識の最小テンプレートです。
実際のチームで使う際は、privateリポジトリを作成してこの内容を配置してください。
会社・プロジェクト固有の情報は含めていません。

## 新メンバーへの案内

1. 個人用の `personal-ai-loop` をcloneし、使うAIツールへ導入する。
2. このテンプレートから作ったチームリポジトリを、担当プロジェクトへ接続する。

```bash
npm install -g teamai-cli
cd /path/to/project
teamai init https://github.com/YOUR-ORG/YOUR-TEAM-REPO --scope project
```

上のURLは実際のチームリポジトリへ置き換えます。
管理者は `teamai.yaml` の `team` と `repo` も変更してください。
GitホスティングがGitHub以外なら `provider` も合わせます。
個人用リポジトリの公開URLが決まったら、このREADMEにリンクを追記してください。

## 担当範囲

| 個人側 | チーム側 |
|---|---|
| 個人の好み、補助の受け方 | 成果物・開発手順の規約 |
| 改善候補の検出と振り返り | 採用する共通知識のレビュー |
| 個人のメモリ・会話ログ | 一般化した設計判断・手順 |
| `personal-*` スキル | 必要になったチーム専用スキル |

`rules/team-boundaries.md` を配布ルールとし、採用済みの知識を `docs/` に置きます。
使わないスキル、エージェント、MCP、Hooksの空の雛形は用意しません。

## 知識を追加する

個人側の振り返りで共有候補が出たら、同じトピックが既にないか確認し、既存ファイルを更新するか新規ノートを作ります。
ノートには結論、適用条件、検証方法を含め、 `docs/README.md` にリンクを追加します。
通常のブランチとPRでレビューし、採用後はTeamAIで配布します。
個人のキュー・会話ログ・プロファイルや端末の絶対パスは持ち込みません。

Gitホストでデフォルトブランチにレビュー必須の保護を設定してください。
このリポジトリ内の規約だけでは、直接pushを技術的に禁止できません。

## TeamAIとの共存上の制約

初期設定は自動recallなし、カスタムHooks・MCPの自動反映なし、シェル設定への環境変数注入なしです。
**これらはTeamAI内蔵の共有提案・利用状況収集を停止する設定ではありません。**
確認した0.22.0では内蔵共有提案だけの停止設定がなく、個人側と通知が重複する可能性があります。
個人の振り返りを唯一の入口にする場合は、TeamAI側にその停止設定を追加してからチーム展開してください。
当面併用する場合も、会話全体の共有経路は使わず、選別済みの変更を通常のPRで提案します。

このテンプレートは構成例です。チームの認証・同期・ブランチ保護を含む実環境テストは、チームリポジトリを用意した後に行います。
参照: [TeamAI公式](https://github.com/Tencent/teamai-cli)、[設定ガイド](https://github.com/Tencent/teamai-cli/blob/main/docs/usage-guide.md)。
